# RemoteX v1.2 implementation plan

Date: 2026-08-12

## Baseline

- `v1.1.0` (`328203a`) is the compatibility and behavior baseline.
- The working tree already contains the small post-v1.1 application-updater and
  Windows GUI-subsystem changes. They are folded into v1.2.0 and must not be
  published separately.
- Existing authorization, permission intersection, E2EE, replay protection,
  bounded queues, file-root confinement, local visibility, and local disconnect
  behavior remain mandatory.

## Delivery scope

1. Replace the separate controller and local-device server fields with one
   persisted server configuration, including a conservative migration that
   never silently overwrites a custom v1.1 value.
2. Add a resumable first-run flow that verifies and saves the server without
   registering the device. Existing configured users skip it and can reopen it
   from Settings. Remote access remains an explicit, separate setting.
3. Measure the current base64 video IPC path and reduce hot-path work with a
   latest-frame renderer that does not put every frame in React application
   state. Track received, rendered, dropped, latency, and frame-rate metrics.
4. Split the desktop frontend into typed API, model, video, diagnostics, setup,
   and view modules. Keep `App` responsible for coordination rather than all
   rendering and transport details.
5. Consolidate CSS into `design-tokens.css`, `layout.css`, `components.css`, and
   `session.css`; remove the legacy stylesheet cascade and apply the graphite,
   restrained Apple-inspired visual direction with Windows-native behavior.
6. Add connection-stage copy, categorized friendly errors, keyboard focus and
   reduced-motion support, plus a `Ctrl+Shift+D` diagnostics overlay.
7. Make release validation a dependency of artifact publication, verify tag,
   workspace, UI, Tauri, and artifact versions, document signed tags and
   optional Authenticode signing, and add performance/release checklists.
8. Run formatting, linting, tests, audits, UI builds, release packaging, PE GUI
   subsystem validation, and multi-size desktop checks. Produce a local NSIS
   installer and checksum only; do not commit, tag, push, or publish.

## Implementation order

- P0: unified server configuration and migration.
- P0: first-run server setup and retry states.
- P0: video benchmark, latest-frame scheduling, renderer statistics.
- P0: release validation gate.
- P1: frontend decomposition, CSS consolidation, UI and language polish.
- P1: friendly connection errors and version-neutral documentation.
- P2: diagnostics, benchmark tooling, signed-tag and Authenticode guidance.
- Final: full verification, window-size review, and local installer build.

## Acceptance criteria

- Production defaults contain no localhost control or relay endpoint.
- Incoming and outgoing use the same server and CA configuration.
- A conflicting custom v1.1 configuration is surfaced for an explicit choice.
- First run can retry a failed server check without restarting.
- Existing configured users do not see first-run setup automatically.
- Controller-only use never requires registering the local device; the local
  device panel appears only after Remote Access is explicitly enabled.
- Video receipt does not cause a full application React render per frame.
- Diagnostics show received/rendered/dropped frames and latency without logging
  frame contents, secrets, clipboard data, paths, or keys.
- The UI remains usable at 1280x720, 1366x768, and 1920x1080 with keyboard-only
  navigation, visible focus, sufficient contrast, and reduced motion.
- Release jobs cannot publish unless validation and version checks pass.
- A versioned local v1.2.0 NSIS installer and SHA-256 file are produced; no
  GitHub release or repository mutation occurs.

## Explicit non-goals

- No mobile or macOS client, audio, account system, or full ICE/STUN/TURN stack.
- No unsafe hot-code replacement. Application updates remain signed installer
  updates so native Rust and permission boundaries update atomically.
- No weakening of interactive approval or independent capability permissions.
