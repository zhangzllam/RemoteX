# RemoteX UI and connection passwords

Local implementation and verification: 2026-09-09. Version remains 1.3.0
Unreleased. No commit, push, tag, GitHub release, or automatic installation.

## Design decisions

- Separate incoming and outgoing connections into two consistently aligned
  cards. Keep this computer's ID, password and remote-access switch together.
- Reduce decorative gradients, use semantic light/dark tokens, and reserve
  strong blue for primary actions. Compact the header and card spacing on
  laptop-height windows so recent connections remain easier to reach.
- Keep the Windows window frame and input conventions. Apply Apple HIG's
  hierarchy, legibility, predictable controls, and reduced-motion principles.
- Keep Chinese and English, accessible labels, focus indicators, and a
  keyboard-submittable connection form. Reuse existing SVG icons.

References reviewed:

- [Linear: How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui)
  — quieter chrome and clearer navigation/content hierarchy.
- [TeamViewer: Where to find my ID and password](https://www.teamviewer.com/en-us/global/support/knowledge-base/teamviewer-remote/remote-control/where-to-find-my-id-and-password/)
  — discoverable credentials within the incoming-connection area.
- Installed Apple HIG, Figma design-system-rules and Figma implementation skills
  were read. No Figma file or callable MCP connection was available; this uses
  RemoteX's existing design system, not a claim of matching a Figma frame.

## Behavior

- First activation without an existing password generates a readable 16-character
  password from the OS random generator and enables password authorization.
- Existing passwords and an explicitly chosen approval-only mode are preserved.
  Random regeneration and custom passwords are available from Home and Security.
- Passwords are protected locally using Windows DPAPI. Settings responses and
  browser persistence do not include plaintext. Only explicit reveal/copy
  requests return it to the local UI.
- Wrong presented passwords are rejected. With no password, the existing local
  approval flow remains available. Configured input/file/clipboard permissions
  still bound every accepted session.
- Changing the password restarts a running Agent with the new configuration.
  Password changes are blocked during an incoming session, including when the
  editor was opened before the session began. Disabling remote access remains
  available to stop access.
- Local and outgoing password displays hide on window blur or page hiding.
  A delayed local reveal response cannot redisplay the password after blur.
- Connecting to this computer is blocked in the Home form. Switching the target
  clears the old outgoing password. Recent entries support search, removal and undo.

## Remaining physical acceptance

Browser mocks and readiness checks do not establish a two-computer remote
session. Verify actual Windows install/upgrade, two computers on different
networks, correct/wrong/rotated passwords, screen display, keyboard/mouse,
explicit permission changes, and reconnect behavior before declaring full
cross-network acceptance. Linux runtime validation remains separate.
