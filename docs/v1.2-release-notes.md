# RemoteX v1.2.1

RemoteX v1.2.1 improves first-run setup, video delivery, desktop usability, and
release integrity while keeping remote access explicit and self-hosted.

## Highlights

- Unified controller and local-device server configuration with conservative
  migration from v1.1 and an explicit choice when existing values conflict.
- Removed device registration as a prerequisite for controller-only use.
  Incoming Remote Access remains optional and can be enabled independently.
- Added a resumable first-run setup flow for server verification, device
  naming, Remote Access, and recovery from configuration errors.
- Replaced the default per-frame base64 event path with a Tauri binary Channel,
  latest-frame scheduling, and received/rendered/dropped/latency diagnostics.
- Refined Home, Devices, Files, Settings, and About with a responsive Windows
  desktop layout, dark/light/system appearance modes, and Simplified Chinese
  and English localization.
- Added signed in-app updates, release validation, signed tags, optional
  Authenticode signing, and reproducible artifact checks.

## Upgrade notes

- Existing v1.1 server settings are migrated on first launch. If controller
  and local-device settings contain different custom servers, RemoteX asks
  which value to keep.
- Existing controller-only installations can connect without registering the
  local computer. Enable Remote Access only if this computer should accept
  incoming connections.
- Appearance and language preferences are stored locally and apply immediately.

## Security behavior

- Remote sessions continue to require explicit authorization unless unattended
  access is deliberately enabled.
- Session payloads remain end-to-end encrypted, and locally stored secrets are
  protected with Windows DPAPI.
- Application updates require a signed installer and a matching updater
  signature; RemoteX does not hot-update native code.

## Self-hosting changes

- Controller and local-device components now use one server configuration.
- Production configuration still requires HTTPS and has no localhost default.
- No hosted RemoteX cloud or account service is introduced by this release.

## Known limits

- The Windows installer is Authenticode-signed only when the release workflow
  is configured with a trusted certificate. The Tauri updater signature is
  still mandatory.
- Direct connection is not a full ICE/STUN/TURN implementation.
- Mobile and macOS clients, audio, and a hosted cloud service are not included.
